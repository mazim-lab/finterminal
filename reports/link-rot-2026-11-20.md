# Link-rot sentinel report, 2026-11-20

Checked 123 front-facing links: 8 deal URLs with no `expiresAt` in `src/data/deals.ts`, 98 unique `sourceUrl` links in `src/data/news.ts` (101 news items, 3 of them reusing a URL already checked once), and 17 issuer links on the three rate pages.

No deal link was confirmed DEAD. All 8 came back HTTP 403 (bot-walled on Newegg.ca and BestBuy.ca), which is INCONCLUSIVE, not DEAD, per the sentinel's rules. No `deals.ts` edit was made. The 90-day housekeeping cutoff for today is 2026-08-22, and the oldest `expiresAt` anywhere in `deals.ts` is 2026-09-09, so nothing qualifies for removal either. This is a report-only run.

Three DEAD links were found, all in `src/data/news.ts`. News is an append-only archive and was not edited; these are reported for a human to review.

**A note on classification this run.** This run's instructions set a narrow, literal definition of DEAD: HTTP 404, 410, a redirect to the site's root, or a clear "not found" / "no longer available" page. Recent prior reports (Nov 14, 17, 18, 19) additionally flagged pages that load cleanly (HTTP 200) but show different, generic, or stale content that no longer substantiates the specific claim in the news item, treating that as "dead for sourcing purposes." That broader rule is not written in `docs/CRON_RUNBOOK.md`; this run follows the narrower definition actually given to it, so the DEAD count below is much smaller than Nov 19's 28. The pages those prior reports flagged (RBC Avion, several Air Canada evergreen pages reused across dated items, WestJet Triangle/advisories pages, etc.) mostly still load fine today and are technically LIVE under today's rule; they are a content-staleness concern for a human writer to re-source, not a broken link, so they are intentionally not repeated here. A human may want to reconcile which definition this routine should use going forward.
